# Ali101 – انتشار خودکار کانفیگ‌های انتخاب‌شده در تلگرام

**تنظیم جدید: یک کانفیگ در هر نوبت؛ فاصلهٔ هدف ۱۱ دقیقه؛ هر کانفیگ یک پیام جدا؛ بدون دکمهٔ کپی.**

## روش کار

1. شما هر روز کانفیگ‌هایی را که **شخصاً از ایران تست کرده‌اید**، هر کدام در یک خط فایل `configs.txt` مخزن می‌گذارید.
2. GitHub Actions حدود هر ۱۱ دقیقه یک‌بار ربات را اجرا می‌کند. در هر اجرای مجاز فقط **یک کانفیگ** انتخاب و به کانال فرستاده می‌شود.
3. بالای پست نام Ali101 و هشتگ‌های فارسی/انگلیسی قرار دارد؛ **وسط پیام، لینک کامل داخل بلوک کد `<pre>`** قرار می‌گیرد؛ پایین پست لینک کانال درج می‌شود. **هیچ دکمه‌ای افزوده نمی‌شود.** بلوک کد در کلاینت‌های پشتیبانی‌شده تلگرام به‌راحتی کپی می‌شود، اما ظاهر و رفتار یک‌لمسی به نسخهٔ تلگرام بستگی دارد.
4. `state.json` نگه می‌دارد چه لینک‌هایی فرستاده شده‌اند. تا تمام فهرست ارسال نشود، تکرار نمی‌کند و بعد چرخه را دوباره شروع می‌کند. افزودن خطوط جدید به `configs.txt` نیاز به ویرایش کد ندارد.

> این نسخه فقط **ساختار لینک‌ها** را می‌سنجد؛ تست زندهٔ VPN یا سازگاری در ایران انجام نمی‌دهد، چون خودتان این تست را قبول کرده‌اید. سرور شخصی و نصب هیچ نرم‌افزاری روی کامپیوتر لازم نیست.

## نکته مهم درباره «دقیقاً هر ۱۱ دقیقه»

GitHub Actions تضمین اجرای رأس ۱۱ دقیقه را نمی‌دهد: `cron: '*/11 * * * *'` در دقیقه‌های ۰، ۱۱، ۲۲، ۳۳، ۴۴، ۵۵ هر ساعت فراخوانی می‌شود؛ در تغییر ساعت فاصله ۵ دقیقه است. **ربات حداقل ۱۱ دقیقه بین دو ارسال موفق را کنترل می‌کند**، بنابراین ممکن است آن نوبت کوتاه را رد کند و نوبت بعدی با فاصله حدود ۱۶ دقیقه برسد. تأخیرها یا حذف نوبت‌های GitHub هم ممکن‌اند. برای انتشار کاملاً دقیق، به زمان‌بند قابل‌اطمینان‌تری نیاز است.

## جایگزینی فایل‌ها در GitHub

1. از مخزن `6badifar9/ali101-v2ray-bot` در GitHub بکاپ بگیرید (`Code → Download ZIP`).
2. ZIP این بسته را باز کنید؛ **محتویات داخل آن** را در ریشه مخزن، همراه با مسیر `.github/workflows/ali101-publish.yml` بارگذاری کنید، نه خود فایل ZIP.
3. **`configs.txt` قبلی را حفظ کنید.** این بسته `configs.txt` ندارد؛ فقط `configs.example.txt` برای نمونه دارد. فایل `state.json` را بهتر است **حفظ کنید** تا فهرست کانفیگ‌های قبلاً ارسال‌شده از بین نرود (کد جدید با ساختار state قدیم سازگار است). اگر اولین نصب است، state نمونه هم معتبر است.
4. در GitHub: `Settings → Secrets and variables → Actions`، سکرت `BOT_TOKEN` را با توکن ربات مقداردهی کنید؛ توکن را هرگز در فایل‌های عمومی نگذارید.
5. ربات باید در کانال `@Ali101_free_V2ray` ادمین با دسترسی ارسال پست باشد. اگر شناسهٔ کانال عوض شد، مقدار `CHANNEL_ID` را در workflow به‌روز کنید.
6. در `Settings → Actions → General → Workflow permissions`، اگر لازم بود **Read and write permissions** را فعال کنید تا Action بتواند فایل `state.json` را commit کند.
7. از بخش `Actions`، workflow با نام **Ali101 - Send one V2Ray config** را یک بار با `Run workflow` اجرا کنید و کانال را بررسی کنید. این یک ارسال آزمایشی واقعی است، مگر محدودیت زمانی از قبل وجود داشته باشد.
8. **workflowهای قدیمی ارسال کانفیگ را غیرفعال کنید** تا چند ربات همزمان پست نگذارند.

## بررسی و تغییر تنظیمات

- زمان‌بندی: `.github/workflows/ali101-publish.yml` → `cron: '*/11 * * * *'`
- حداقل فاصلهٔ انتشار: متغیر `SEND_INTERVAL_MINUTES: '11'`
- کانال: `CHANNEL_ID: '@Ali101_free_V2ray'`
- آزمایش محلی (اختیاری): `python -m unittest discover -s tests -v`
- تست اعتبارسنجی بدون ارسال: `python bot.py --dry-run` (نیازمند `configs.txt`)

در زمان آپلود، `configs.example.txt` را به‌جای `configs.txt` آپلود نکنید. اگر به‌روزرسانی `configs.txt` هم‌زمان با اجرای ربات انجام شود، احتمال تعارض هنگام push فایل state وجود دارد؛ یک بار اجرای مجدد معمولاً لازم می‌شود. همچنین ارسال موفقی که پیش از ذخیره‌شدن state با خطای GitHub مواجه شود، ممکن است تکرار شود؛ دقیقاً یک‌بار در همهٔ شرایط تضمین نیست.
